## The feature: area damage

A fireball explodes and damages every enemy within its radius. The code loops over the enemy list, checks the distance, and subtracts hp. It compiles, it runs, and no enemy ever dies.

## The careless version: auto copies

```cpp
#include <cstdio>
#include <vector>

struct Enemy { const char* name; float x, y; int hp; };

void explode(std::vector<Enemy>& enemies, float cx, float cy, float r, int dmg) {
    for (auto e : enemies) {                       // e is a copy
        float dx = e.x - cx, dy = e.y - cy;
        if (dx * dx + dy * dy <= r * r) e.hp -= dmg;
    }
}

int main() {
    std::vector<Enemy> enemies{{"slime", 1, 1, 20}, {"bat", 2, 0, 15}, {"ghost", 9, 9, 40}};
    explode(enemies, 0, 0, 3, 25);
    for (const auto& e : enemies) std::printf("%-5s hp %d\n", e.name, e.hp);
}
```
```text
slime hp 20
bat   hp 15
ghost hp 40
```

## What went wrong

`auto e` follows the by-value deduction rule: it drops references, so `e` is a fresh copy of each enemy. The fireball damaged the copies, which were destroyed at the end of each loop iteration. The real enemies kept full hp.

The fix is one character: `for (auto& e : enemies)`. With `auto&`, `e` is a reference to the element. To read without changing, write `const auto&`, which also avoids copying a big object.

## The three deduction cases

`auto` follows template argument deduction. Given `const int ci = 1;` and a call `f(ci)`:

- `template<class T> void f(T)` gives T = int (const dropped: it's a copy)
- `template<class T> void f(T&)` gives T = const int
- `template<class T> void f(T&&)` gives T = const int&

![Deduction table: argument const int& through by-value, by-reference and forwarding parameters](/diagrams/cpp-systems/04-templates/01-templates-and-deduction.png)

The by-value rule makes sense: a copy is a new object, so the original's `const` and reference-ness do not apply to it. The surprise is only that `auto` looks harmless.

## Worked example: a Vec2 template

A class template for the engine's 2D vectors, with CTAD so callers write `Vec2{3, 4}`:

```cpp
#include <cstdio>

template <class T>
struct Vec2 {
    T x, y;
    Vec2 operator+(Vec2 o) const { return {x + o.x, y + o.y}; }
    Vec2 operator*(T k) const { return {x * k, y * k}; }
};

template <class T>
T dot(Vec2<T> a, Vec2<T> b) { return a.x * b.x + a.y * b.y; }

int main() {
    Vec2 tile{3, 4};                  // CTAD: Vec2<int>
    Vec2 pos{1.5f, 2.0f};             // CTAD: Vec2<float>
    Vec2 vel{0.5f, -1.0f};
    auto next = pos + vel * 2.0f;     // physics step
    std::printf("tile %d,%d  dot %d\n", tile.x, tile.y, dot(tile, tile));
    std::printf("next position %.1f,%.1f\n", next.x, next.y);
}
```
```text
tile 3,4  dot 25
next position 2.5,0.0
```

`Vec2{3, 4}` works because C++20 deduces aggregate class templates from their members. `dot(tile, pos)` would not compile: T cannot be both `int` and `float`, which is what we want. Mixing tile coordinates and physics coordinates without a conversion is usually a bug.

## When to use it, and when not

- Use `auto` for long or unnameable types (iterators, lambdas), and `auto&` or `const auto&` in loops over objects.
- Use plain `auto` in a loop only for small values you mean to copy (`for (int id : ids)`).
- Use CTAD for obvious cases (`std::vector v{1, 2, 3}`, `Vec2{1.0f, 2.0f}`). Spell the type out when the deduced one would surprise a reader: `std::vector v{"a", "b"}` deduces `std::vector<const char*>`, not strings.
- Do not write a template for one type. Write it when the second type shows up.
