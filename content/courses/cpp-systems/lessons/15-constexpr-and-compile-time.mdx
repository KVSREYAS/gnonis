## The feature: sprite sheets and level-up tables

The renderer cuts a 256x256 sprite sheet into square tiles. The art team switches from 32-pixel tiles to 48-pixel tiles, and someone updates the constant.

## The careless version: a check that never runs

```cpp
#include <cstdio>

const int SHEET = 256;
const int TILE  = 48;                         // was 32
const int TILES_PER_ROW = SHEET / TILE;       // 5, with 16 pixels left over

int main() {
    // the renderer assumes the tiles fill the sheet exactly
    int last_x = (TILES_PER_ROW - 1) * TILE;
    std::printf("tiles per row: %d\n", TILES_PER_ROW);
    std::printf("last tile starts at x=%d, sheet ends at x=%d: %d pixels unused\n",
                last_x, SHEET, SHEET - (last_x + TILE));
}
```
```text
tiles per row: 5
last tile starts at x=192, sheet ends at x=256: 16 pixels unused
```

## What went wrong

256 is not a multiple of 48. The integer division silently rounded down, the rightmost 16 pixels of every row are never drawn, and tile indices computed by the art tool (which counted 6 per row, the last one cut off) no longer match the game's. Every sprite after the first row comes out shifted. Nobody notices until a tester reports that the slime looks like a bat.

The rule "TILE must divide SHEET" was known when the constants were written. It could have been checked right then.

## The fix: static_assert on constants

`static_assert(condition, message)` is checked by the compiler. If it is false, the build fails:

```cpp
constexpr int SHEET = 256;
constexpr int TILE  = 48;
static_assert(SHEET % TILE == 0, "sprite sheet must be a whole number of tiles");
constexpr int TILES_PER_ROW = SHEET / TILE;

int main() { return TILES_PER_ROW; }
```
```text
game.cpp:3: error: static assertion failed: sprite sheet must be a whole number of tiles
```

The mistake can no longer reach a tester, or a player. `constexpr` on a variable means its value is known while compiling, so it can be used in `static_assert`, as an array size, or as a template argument.

## constexpr functions: tables built by the compiler

A `constexpr` function can run while compiling when its arguments are constants. Loops, local variables and `std::array` are all allowed. Here the XP needed for each level is computed by the compiler and baked into the program:

```cpp
#include <array>
#include <cstdio>

constexpr std::array<int, 11> make_xp_table() {
    std::array<int, 11> t{};
    for (int lv = 1; lv <= 10; ++lv) t[lv] = t[lv - 1] + 100 * lv;   // 100, 300, 600, ...
    return t;
}

constexpr auto XP = make_xp_table();          // computed while compiling
static_assert(XP[3] == 600);                  // tested while compiling

int main() {
    int player_xp = 1234;
    int lv = 0;
    while (lv < 10 && player_xp >= XP[lv + 1]) ++lv;
    std::printf("xp %d -> level %d (next at %d)\n", player_xp, lv, XP[lv + 1]);
}
```
```text
xp 1234 -> level 4 (next at 1500)
```

The table costs nothing at startup: it is stored in the executable as data. If the formula has a bug, the `static_assert` fails the build.

## consteval and if constexpr

- `consteval` makes a function that **must** run at compile time. Use it for things that would be wrong at runtime, like hashing an asset name to an id: `constexpr auto id = asset_id("slime.png");`.
- `if constexpr (cond)` picks a branch while compiling, per template instantiation. The other branch is thrown away, so it may contain code that would not compile for that type:

```cpp
template <class T> constexpr std::size_t bytes_of() {
  if constexpr (std::is_same_v<T, bool>) return 1;   // save files pack bools in 1 byte
  else return sizeof(T);
}
```

## When to use it, and when not

- Use `constexpr` constants and `static_assert` for every rule that relates constants: tile sizes, buffer sizes, the number of entries in an enum and its name table.
- Use `constexpr` functions for small tables (XP curves, sine tables, bit counts) and for helpers you want to test with `static_assert`.
- Do not compute huge tables at compile time: compile time and the executable size grow. Generate megabytes of data with a tool, or at load time.
- Use `consteval` only when a runtime call would be a mistake.
