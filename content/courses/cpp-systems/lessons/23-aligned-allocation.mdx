## The feature: particle buffers for SIMD

The SIMD module will update four particle positions with one instruction. The aligned load instructions it uses (`_mm_load_ps`, four floats at once) require the address to be a multiple of 16. The particle buffers are carved out of one big byte pool that the level allocates up front.

## The careless version: carve at any offset

```cpp
#include <cstdint>
#include <cstdio>
#include <cstdlib>
#include <xmmintrin.h>

// the SIMD step: move 4 particles at once with aligned loads
__attribute__((noipa)) void step4(float* x, const float* vx) {
    _mm_store_ps(x, _mm_add_ps(_mm_load_ps(x), _mm_load_ps(vx)));
}

int main() {
    char* pool = static_cast<char*>(std::malloc(1 << 20));   // the level's memory pool
    std::size_t used = 0;
    auto carve = [&](std::size_t bytes) { char* p = pool + used; used += bytes; return p; };

    carve(13);                                               // 13 bytes of enemy names
    float* xs  = reinterpret_cast<float*>(carve(4096));      // particle x positions
    float* vxs = reinterpret_cast<float*>(carve(4096));      // particle x velocities
    for (int i = 0; i < 1024; ++i) { xs[i] = float(i); vxs[i] = 1.0f; }
    std::printf("xs at address %% 16 = %zu\n", reinterpret_cast<std::uintptr_t>(xs) % 16);
    std::fflush(stdout);
    step4(xs, vxs);
    std::printf("moved: x[0] = %.1f\n", xs[0]);
    std::free(pool);
}
```
```text
xs at address % 16 = 13
Segmentation fault
[exit code 139]
```

## What went wrong

`malloc` returns 16-byte aligned memory, but `pool + 13` is not. `_mm_load_ps` on an address that is not a multiple of 16 raises a general protection fault, and the process dies with a segmentation fault (exit code 139 is 128 + signal 11). With a different order of `carve` calls, the offset happens to be a multiple of 16 and the game runs fine, which is why this kind of crash appears on "some levels" only.

## The fix: round the offset up

For a power-of-two alignment `a`, `a - 1` is a mask of the low bits. Adding `a - 1` and clearing those bits rounds up to the next multiple:

```cpp
#include <cstdint>
#include <cstdio>
#include <cstdlib>
#include <xmmintrin.h>

__attribute__((noipa)) void step4(float* x, const float* vx) {
    _mm_store_ps(x, _mm_add_ps(_mm_load_ps(x), _mm_load_ps(vx)));
}

constexpr std::size_t align_up(std::size_t x, std::size_t a) { return (x + a - 1) & ~(a - 1); }

int main() {
    char* pool = static_cast<char*>(std::malloc(1 << 20));
    std::size_t used = 0;
    auto carve = [&](std::size_t bytes, std::size_t align) {
        used = align_up(used, align);                        // round the offset up first
        char* p = pool + used; used += bytes; return p;
    };
    carve(13, 1);
    float* xs  = reinterpret_cast<float*>(carve(4096, 16));
    float* vxs = reinterpret_cast<float*>(carve(4096, 16));
    for (int i = 0; i < 1024; ++i) { xs[i] = float(i); vxs[i] = 1.0f; }
    std::printf("xs at address %% 16 = %zu, offset in pool %td\n",
                reinterpret_cast<std::uintptr_t>(xs) % 16, reinterpret_cast<char*>(xs) - pool);
    step4(xs, vxs);
    std::printf("moved: x[0] = %.1f\n", xs[0]);
    std::free(pool);
}
```
```text
xs at address % 16 = 0, offset in pool 16
moved: x[0] = 1.0
```

`align_up(13, 16)` is `(13 + 15) & ~15` = 28 & ~15 = 16. This only works because the pool itself is 16-aligned; for 64-byte alignment the pool must come from `std::aligned_alloc(64, ...)`.

## The standard tools

- `alignas(N)` on a type or variable: `struct alignas(16) Vec4 { float v[4]; };`. Since C++17, `new Vec4[n]` and `std::vector<Vec4>` respect it.
- `std::aligned_alloc(align, size)`: size must be a multiple of align; free with `std::free`.
- For SIMD you can also use the unaligned loads (`_mm_loadu_ps`), which accept any address. On modern CPUs they cost the same as aligned loads when the data happens to be aligned, and a little more when a load spans two cache lines.

## When to use it, and when not

- Align buffers that SIMD code reads with aligned loads, and per-thread data that must sit on its own cache line.
- Every custom allocator (pools, arenas) must round offsets up to the alignment of what it hands out. Forgetting it is undefined behaviour even without SIMD.
- Do not over-align everything to 64: it wastes memory between small objects.
