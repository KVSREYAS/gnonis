## The feature: wind

A gust of wind pushes every particle to the right: `x += wind * dt`. One field, one addition, 2,000,000 particles. The particles already live in a contiguous `std::vector<Particle>`, so the layout module's lesson seems learned.

## The careless version: a contiguous array of fat structs

```cpp
#include <chrono>
#include <cstdio>
#include <vector>

struct Particle {                    // 64 bytes: everything a particle might need
    float x, y, vx, vy;
    float r, g, b, a;
    float size, rotation, life, max_life;
    int   texture, flags, emitter, seed;
};

int main() {
    const int N = 2'000'000;
    std::vector<Particle> aos(N, Particle{});
    std::vector<float> xs(N, 0.0f);                  // SoA: just the x field
    auto ms = [](auto d) { return std::chrono::duration<double, std::milli>(d).count(); };
    double t_aos = 0, t_soa = 0;
    for (int rep = 0; rep < 5; ++rep) {
        auto t0 = std::chrono::steady_clock::now();
        for (auto& p : aos) p.x += 3.0f * 0.016f;
        auto t1 = std::chrono::steady_clock::now();
        for (float& x : xs) x += 3.0f * 0.016f;
        auto t2 = std::chrono::steady_clock::now();
        t_aos += ms(t1 - t0); t_soa += ms(t2 - t1);
    }
    std::printf("sizeof(Particle) = %zu\n", sizeof(Particle));
    std::printf("AoS wind: %.2f ms   SoA wind: %.2f ms\n", t_aos / 5, t_soa / 5);
    std::printf("(check %.2f %.2f)\n", aos[7].x, xs[7]);
}
```
```text
sizeof(Particle) = 64
AoS wind: 5.24 ms   SoA wind: 0.39 ms
(check 0.24 0.24)
```

## What went wrong

The AoS array is contiguous, but each 64-byte cache line holds exactly one particle, of which the wind loop uses 4 bytes. To update 2,000,000 `x` values it streams 128 MB through the caches. The SoA loop streams 8 MB, the `x` values alone, packed 16 per line. Same work, a fraction of the memory traffic.

There is a second effect: with `x` values next to each other, the compiler loads 4 or 8 of them into one SIMD register and adds to all at once. With AoS it would have to collect `x` values 64 bytes apart.

## The fix: one array per field

```cpp
struct Particles {
    std::vector<float> x, y, vx, vy;
    std::vector<float> r, g, b, a;
    std::vector<float> life;
    // ...
    std::size_t size() const { return x.size(); }
};
```

Each system touches only the arrays it needs: wind touches `x`, the fade system touches `a` and `life`, the renderer reads `x`, `y`, `r`, `g`, `b`, `a` and `size`.

The price: adding or removing a particle means touching every array, and they must stay the same length. Wrap that in `spawn()` and `kill()` functions so no other code can get it wrong.

## When to use it, and when not

- Use SoA for large collections processed field by field in hot loops: particles, physics bodies, the ECS component arrays.
- Keep AoS when code usually needs all fields of one element at once, or the collection is small.
- A middle ground is common: group fields always used together (`struct Vec2 { float x, y; }`) and store an array of those.
