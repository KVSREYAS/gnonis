## The feature: skipping dead particles

Particles die at random moments: when their life runs out, or when they hit a wall. Dead slots are reused later. So at any moment about half of the array is dead, in no particular order, and the update loop checks `alive` for each one.

## The careless version: a branch on random data

```cpp
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <random>
#include <vector>

struct Particle { float x, vx; int alive; int hits; };

__attribute__((noinline)) long update(std::vector<Particle>& ps) {
    long moved = 0;
    for (auto& p : ps) {
        if (p.alive) { p.x += p.vx; ++moved; }    // half are dead, at random
        else         { p.hits = 0; }
    }
    return moved;
}

__attribute__((noinline)) long update_branchless(std::vector<Particle>& ps) {
    long moved = 0;
    for (auto& p : ps) {
        p.x += p.vx * static_cast<float>(p.alive);   // alive is 0 or 1: dead ones add zero
        p.hits *= p.alive;
        moved += p.alive;
    }
    return moved;
}

int main() {
    const int N = 4'000'000;
    std::vector<Particle> ps(N);
    std::mt19937 rng(5);
    for (auto& p : ps) p = Particle{0, 1, int(rng() & 1), 0};
    auto ms = [](auto d) { return std::chrono::duration<double, std::milli>(d).count(); };
    auto t0 = std::chrono::steady_clock::now();
    long a = update(ps);
    auto t1 = std::chrono::steady_clock::now();
    long b = update_branchless(ps);
    auto t2 = std::chrono::steady_clock::now();
    std::partition(ps.begin(), ps.end(), [](const Particle& p) { return p.alive; });
    auto t3 = std::chrono::steady_clock::now();
    long c = update(ps);
    auto t4 = std::chrono::steady_clock::now();
    std::printf("if (alive), random order:  %5.2f ms (%ld moved)\n", ms(t1 - t0), a);
    std::printf("branchless, random order:  %5.2f ms (%ld moved)\n", ms(t2 - t1), b);
    std::printf("if (alive), partitioned:   %5.2f ms (%ld moved)\n", ms(t4 - t3), c);
}
```
```text
if (alive), random order:  15.13 ms (2000050 moved)
branchless, random order:   3.68 ms (2000050 moved)
if (alive), partitioned:    2.49 ms (2000050 moved)
```

(One run on the course machine, g++ -O2.)

## What went wrong

The first and third loops run the same code on the same particles, just in a different order. The difference is the **branch predictor**. The CPU does not wait to find out whether `p.alive` is true; it guesses and keeps running instructions down the guessed path. A right guess costs nothing. A wrong guess throws that work away, roughly 15-20 cycles.

With alive and dead mixed at random, no pattern exists and about half the guesses are wrong: two million mispredictions. After `std::partition` moves the live particles to the front, the branch is "true, true, true... false, false, false", and the predictor is almost always right.

## Two fixes

1. **Make the branch predictable.** Keep live particles at the front: kill by swap-and-pop (the SoA lesson), or partition once per frame. Then the loop over `[0, live_count)` needs no `alive` check at all.
2. **Remove the branch.** Compute the result for every particle with arithmetic: `x += vx * alive` adds zero for dead ones. There is no jump to mispredict, and the compiler can even use SIMD. It does a little extra work for dead particles, which is cheaper than a mispredict.

A ternary (`x += alive ? vx : 0`) is often compiled to a conditional move, but not always: with g++ -O2 on this loop, the ternary version kept its jump and ran as slowly as the `if`. Look at the assembly or measure; do not assume.

The branchless version wins on random data and loses slightly when the branch would have been predictable, because it always does the work.

## When to use it, and when not

- Look for branches inside hot loops whose outcome depends on data with no pattern: alive flags, random hits, type tags in a mixed array.
- Prefer fixing the data (sorted, partitioned, one array per type) over clever bit tricks.
- Do not make code branchless by hand when the branch is predictable (error checks, `if (paused)`): it is already nearly free.
- Check the result: compilers often turn simple `if`s into branchless code on their own. Measure before and after.
