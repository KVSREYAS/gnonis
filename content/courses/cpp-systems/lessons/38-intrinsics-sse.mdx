## The feature: a hand-written particle step

Some particle code is too tangled for the auto-vectorizer: a mix of loads from different arrays, clamps and conditional resets. For those loops we write the SIMD ourselves with intrinsics. The simplest case is the position update, four particles per instruction.

## The careless version: groups of four, and nothing else

```cpp
#include <cstdio>
#include <immintrin.h>
#include <vector>

void step_sse(float* x, const float* vx, std::size_t n, float dt) {
    const __m128 vdt = _mm_set1_ps(dt);
    for (std::size_t i = 0; i + 4 <= n; i += 4) {
        __m128 px = _mm_loadu_ps(x + i);
        __m128 pv = _mm_loadu_ps(vx + i);
        _mm_storeu_ps(x + i, _mm_add_ps(px, _mm_mul_ps(pv, vdt)));
    }
}

int main() {
    const std::size_t alive = 1003;                 // an explosion leaves an odd count
    std::vector<float> x(alive, 0.f), vx(alive, 60.f);
    for (int frame = 0; frame < 60; ++frame) step_sse(x.data(), vx.data(), alive, 1.f / 60);
    for (std::size_t i : {0u, 999u, 1000u, 1001u, 1002u}) std::printf("particle %4zu: x = %.2f\n", i, x[i]);
}
```
```text
particle    0: x = 60.00
particle  999: x = 60.00
particle 1000: x = 0.00
particle 1001: x = 0.00
particle 1002: x = 0.00
```

After one second at 60 units per second every particle should be at about 60. Particles 1000 to 1002 never moved: 1003 is not a multiple of 4, and the loop stopped at the last full group. On screen that is three sparks frozen in the air where the explosion started.

## The concept: vector body plus scalar tail

An intrinsic is a function the compiler turns into one specific instruction. The ones used here:

- `_mm_set1_ps(v)`: all four lanes = v.
- `_mm_loadu_ps(p)` / `_mm_storeu_ps(p, r)`: move 4 floats between memory and a register, any alignment.
- `_mm_add_ps`, `_mm_mul_ps`, `_mm_max_ps`: lane-by-lane arithmetic.

Every hand-written SIMD loop has two parts: the **body**, which handles groups of 4 while `i + 4 <= n`, and the **tail**, a plain loop that finishes the remaining 0 to 3 elements with the same formula.

## The fixed version

```cpp
#include <cstdio>
#include <immintrin.h>
#include <vector>

void step_sse(float* x, const float* vx, std::size_t n, float dt) {
    const __m128 vdt = _mm_set1_ps(dt);
    std::size_t i = 0;
    for (; i + 4 <= n; i += 4) {
        __m128 px = _mm_loadu_ps(x + i);
        __m128 pv = _mm_loadu_ps(vx + i);
        _mm_storeu_ps(x + i, _mm_add_ps(px, _mm_mul_ps(pv, vdt)));
    }
    for (; i < n; ++i) x[i] += vx[i] * dt;          // the tail: 0 to 3 particles
}

int main() {
    const std::size_t alive = 1003;
    std::vector<float> x(alive, 0.f), vx(alive, 60.f);
    for (int frame = 0; frame < 60; ++frame) step_sse(x.data(), vx.data(), alive, 1.f / 60);
    for (std::size_t i : {0u, 999u, 1000u, 1001u, 1002u}) std::printf("particle %4zu: x = %.2f\n", i, x[i]);
}
```
```text
particle    0: x = 60.00
particle  999: x = 60.00
particle 1000: x = 60.00
particle 1001: x = 60.00
particle 1002: x = 60.00
```

The `i` declared outside the body loop carries on into the tail, so each particle is handled exactly once.

## When to use intrinsics, and when not

- Use them for hot loops the compiler will not vectorize after you tried `__restrict`, flat arrays and simpler code, and only after a profiler shows the loop matters.
- Use `loadu`/`storeu` unless you control the alignment. `_mm_load_ps` on an address that is not 16-byte aligned crashes (see the alignment lesson).
- Do not use them for code that runs once per frame on a handful of values: the speed-up is invisible and the code is harder to read.
- SSE intrinsics tie the code to x86. A console or phone build (ARM) needs a NEON version or a scalar fallback.

Note: these exercises need an x86-64 runner (SSE2 is baseline there, no flags needed). Sources: [Intel Intrinsics Guide](https://www.intel.com/content/www/us/en/docs/intrinsics-guide/), Agner Fog, [Optimizing software in C++](https://www.agner.org/optimize/optimizing_cpp.pdf)
