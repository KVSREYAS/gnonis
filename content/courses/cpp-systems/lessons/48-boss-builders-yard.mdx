## Coding task: the projectile pool

The slime king fires up to a few hundred projectiles a second, each living for a moment. They do not share one lifetime, so an arena does not fit: each one dies when it hits something. A **pool** keeps a fixed block of slots and a free list of unused ones, so creating and destroying a projectile is O(1) with no heap traffic and no fragmentation.

  solution={"#include <cstddef>\n#include <new>\n#include <utility>\n#include <array>\ntemplate<class T, std::size_t N> class Pool {\n    alignas(T) std::byte storage_[N][sizeof(T)];\n    std::array<std::size_t, N> next_{}; std::array<bool, N> used_{};\n    std::size_t free_ = 0, live_ = 0;\n    T* slot(std::size_t i) { return std::launder(reinterpret_cast<T*>(storage_[i])); }\npublic:\n    Pool() { for (std::size_t i = 0; i < N; ++i) next_[i] = i + 1; }\n    Pool(const Pool&) = delete; Pool& operator=(const Pool&) = delete;\n    ~Pool() { for (std::size_t i = 0; i < N; ++i) if (used_[i]) slot(i)->~T(); }\n    template<class...
