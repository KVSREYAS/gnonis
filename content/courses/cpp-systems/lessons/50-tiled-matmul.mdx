## The feature: brains for the whole horde

The slime king is not the only one thinking. In the final wave every elite slime runs a smaller copy of the brain. Instead of one matrix-vector product per slime, the game stacks all slimes' inputs into one matrix and runs each layer as a single matrix multiply: `[slimes, inputs] × [inputs, hidden]`.

## The careless version: the textbook loop order

```cpp
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <vector>

__attribute__((noipa)) void mm_ijk(const float* A, const float* B, float* C, int M, int N, int K) {
    for (int i = 0; i < M; ++i)
        for (int j = 0; j < N; ++j) {
            float s = 0;
            for (int k = 0; k < K; ++k) s += A[i * K + k] * B[k * N + j];     // walks down a column of B
            C[i * N + j] = s;
        }
}
__attribute__((noipa)) void mm_ikj(const float* __restrict A, const float* __restrict B, float* __restrict C,
                                   int M, int N, int K) {
    std::fill(C, C + M * N, 0.f);
    for (int i = 0; i < M; ++i)
        for (int k = 0; k < K; ++k) {
            float a = A[i * K + k];
            for (int j = 0; j < N; ++j) C[i * N + j] += a * B[k * N + j];   // walks along a row of B and C
        }
}

int main() {
    const int M = 1024, K = 512, N = 512;          // 1024 slimes, 512 inputs, 512 hidden units
    std::vector<float> A(M * K, 0.5f), B(K * N, 0.25f), C(M * N);
    auto ms = [](auto d) { return std::chrono::duration<double, std::milli>(d).count(); };
    auto t0 = std::chrono::steady_clock::now();
    mm_ijk(A.data(), B.data(), C.data(), M, N, K);
    auto t1 = std::chrono::steady_clock::now();
    float first = C[7];
    mm_ikj(A.data(), B.data(), C.data(), M, N, K);
    auto t2 = std::chrono::steady_clock::now();
    std::printf("i-j-k: %6.1f ms   C[7] = %g\n", ms(t1 - t0), first);
    std::printf("i-k-j: %6.1f ms   C[7] = %g\n", ms(t2 - t1), C[7]);
}
```
```text
i-j-k:  220.2 ms   C[7] = 64
i-k-j:   82.5 ms   C[7] = 64
```

(One run at `-O2`.) Same result, same number of multiplies. On the same machine, `-O3`, which also vectorizes loops whose length is only known at run time, took the i-k-j version to about 21 ms while i-j-k stayed above 200 ms.

## What went wrong

In i-j-k, the inner loop reads `B[k*N + j]` for k = 0, 1, 2...: each step jumps N floats (2 KiB) through memory, a new cache line every time. B is 1 MiB, larger than L1 and L2, so the lines are fetched again for every row of A. The CPU spends its time waiting for memory, and the strided loop cannot be vectorized either.

## The concept: loop order, then tiles

**Loop order.** Swapping to i-k-j does the same additions in a different order. The inner loop walks one row of B and one row of C, both contiguous: every byte of a fetched cache line is used, and the loop can be vectorized (GCC does it at `-O3` here; at `-O2` it only vectorizes loops whose length it can handle cheaply).

**Tiling.** For large matrices even i-k-j streams all of B for each row of A. Tiling splits i, k and j into blocks of T (say 32 or 64) and finishes all the work on one block of A, B and C before moving on. The blocks stay in cache and each loaded value is reused T times. Real BLAS libraries add register blocking and packing on top of this.

## When to use it, and when not

- Use i-k-j (or a transposed B with i-j-k) for any row-major matmul you write yourself. It costs nothing.
- Add tiling when the matrices no longer fit in cache: here B is 1 MiB, a tile of 64×64 floats is 16 KiB.
- For a single slime (one row, M = 1) there is no reuse to gain from tiling: the cost is reading the weights once. That is why a language model generating one token at a time is limited by memory bandwidth.
- In shipped code, call a tuned library (OpenBLAS, Eigen, oneDNN) unless the matrices are tiny or you need full control.

Sources: [Siboehm, How to Optimize a CUDA Matmul](https://siboehm.com/articles/22/CUDA-MMM) (CPU ideas carry over), Goto & van de Geijn, [Anatomy of High-Performance Matrix Multiplication](https://www.cs.utexas.edu/~flame/pubs/GotoTOMS_revision.pdf), [Algorithmica: matmul](https://en.algorithmica.org/hpc/algorithms/matmul/)
