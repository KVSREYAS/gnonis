## The feature: choosing the move

The brain outputs one score per action. The boss has to turn them into one decision, several times a second, without freezing (overflow) and without becoming predictable.

## The careless version: always take the best move

```cpp
#include <cstdio>
#include <random>

const char* actions[4] = {"slam", "jump", "summon", "retreat"};

int greedy(const float* p) {
    int best = 0;
    for (int i = 1; i < 4; ++i) if (p[i] > p[best]) best = i;
    return best;
}
int sample(const float* p, float u) {          // u uniform in [0, 1)
    float c = 0;
    for (int i = 0; i < 4; ++i) { c += p[i]; if (u < c) return i; }
    return 3;                                   // rounding guard
}

int main() {
    float p[4] = {0.45f, 0.30f, 0.15f, 0.10f};   // the brain's view of this situation
    std::mt19937 rng(2026);
    int g[4] = {}, s[4] = {};
    for (int turn = 0; turn < 1000; ++turn) {
        ++g[greedy(p)];
        float u = (rng() >> 8) * (1.0f / 16777216.0f);
        ++s[sample(p, u)];
    }
    std::printf("move      greedy  sampled\n");
    for (int i = 0; i < 4; ++i) std::printf("%-8s %7d %8d\n", actions[i], g[i], s[i]);
}
```
```text
move      greedy  sampled
slam        1000      449
jump           0      302
summon         0      144
retreat        0      105
```

The network thought jumping was a good move 30% of the time, but greedy decoding threw that away: 1000 slams in a row. Players learn "dodge left when he raises his arms" and the fight is over. Sampling keeps the network's preferences (mostly slams) while staying varied.

## The concept: stable softmax, then choose

**Softmax without overflow.** `exp` of a float overflows above about 88.7. Subtract the largest logit first: `exp(z_i - m)` is at most 1, and the probabilities are unchanged because the common factor `exp(-m)` cancels.

**Choosing.**

- **Greedy (argmax)**: deterministic. Right for tests, replays and tutorial bosses.
- **Sampling**: draw u in [0, 1), walk the running sum of p, return the first index where u is below it.
- **Temperature T**: divide the logits by T before softmax. Low T (0.3) is nearly greedy: a focused, harder boss. High T (2) flattens the choices: an erratic, easier boss. One number becomes a difficulty setting.

## When to sample, and when not

- Sample for anything players should not be able to predict: boss moves, enemy taunts, loot choices weighted by rarity.
- Use greedy, or sampling with a fixed seed, when results must repeat: automated tests, replays, lockstep multiplayer where every machine must make the same choice.
- Always use the max-subtracted softmax. The naive version works in testing and fails on exactly the confident, large-score cases that matter.
- Do not sample from probabilities you did not normalize: the running sum must reach 1, or the last action is picked far too often by the rounding guard.

Sources: [Wikipedia: softmax](https://en.wikipedia.org/wiki/Softmax_function), Milakov & Gimelshein, [Online normalizer calculation for softmax (2018)](https://arxiv.org/abs/1805.02867)
