## Class, object, member

A **class** is a user-defined type. It lists **data members** (variables each object holds) and **member functions** (functions that operate on an object).

An **object** is one instance of the class, with its own copy of the data members.

```cpp
class Counter {
public:
    void add() { count_ += 1; }
    int value() const { return count_; }
private:
    int count_ = 0;   // default member initializer
};

Counter a, b;
a.add(); a.add();
b.add();
// a.value() == 2, b.value() == 1
```

Inside a member function, `count_` means "this object's `count_`". The hidden pointer `this` holds the address of the object the function was called on. `a.add()` runs `add` with `this == &a`.

`struct` and `class` are the same, except members of a `struct` are public by default.

## Access control and const

**Access specifiers** decide who may use a member:

- `public`: any code
- `private`: only member functions (and friends) of this class
- `protected`: this class and classes derived from it

Keeping data private lets the class enforce an **invariant**: a rule that is always true for valid objects, such as "balance is never negative". Outside code must go through public functions, which check the rule.

A member function marked `const` after its parameter list promises not to modify the object. You can only call `const` functions on a `const` object:

```cpp
const Counter c;
c.value();  // fine
c.add();    // compile error: add is not const
```

## Constructors and destructors

A **constructor** has the class name and no return type. It runs when an object is created. A **destructor** is `~Name()` and runs when the object is destroyed.

```cpp
class Account {
    std::string owner_;
    long cents_;
public:
    Account(std::string o, long c)
        : owner_(std::move(o)), cents_(c) {   // initializer list
        if (cents_ < 0) cents_ = 0;            // body
    }
    ~Account() {}
};
```

Order of events:

1. Members are initialized in the order they are **declared** in the class, using the **member initializer list** (after the `:`).
2. Then the constructor body runs.

Prefer the initializer list. Members that are `const` or references can only be set there. Mark one-argument constructors `explicit` so the compiler does not use them for silent conversions.

## static members, operators, friends

A **static** data member belongs to the class, not to each object. There is one copy shared by all objects. A static member function has no `this`, so it can only touch static members.

```cpp
struct Id { static int next; int v = next++; };
int Id::next = 0;
```

**Operator overloading** lets `a + b` call a function you write:

```cpp
struct Money {
    long cents;
    Money operator+(Money o) const { return {cents + o.cents}; }
    bool operator==(const Money&) const = default;
};
```

A **friend** function is declared inside the class with `friend`. It is not a member, but it may read private members. It is used when the left operand is not your class, such as `operator<<` for printing to `std::ostream`.

## Inheritance and virtual functions

**Inheritance** creates a **derived** class that contains everything in a **base** class plus its own members: `class Circle : public Shape`.

A **virtual** function can be replaced (**overridden**) in a derived class. When you call it through a base pointer or reference, the program checks the object's actual type at runtime and calls that type's version. This is **dynamic dispatch**.

```cpp
struct Shape {
    virtual double area() const = 0;  // pure virtual
    virtual ~Shape() = default;       // needed!
};
struct Sq : Shape {
    double s;
    double area() const override { return s * s; }
};
std::unique_ptr<Shape> p = std::make_unique<Sq>(Sq{{}, 2});
p->area();   // 4, Sq's version
```

`= 0` makes the class **abstract**: you cannot create a plain `Shape`. `override` asks the compiler to check that you really override something. The base destructor must be virtual so deleting through a base pointer runs the derived destructor.

## How virtual calls work: vtables and slicing

Compilers implement virtual functions with a **vtable**: one table per class holding addresses of its virtual functions. Each object of a class with virtual functions has a hidden pointer, the **vptr**, to its class's table. That adds 8 bytes to the object on x86-64.

A call `p->area()` becomes: load the vptr from the object, load the function address from the table slot for `area`, call it. That indirect call usually cannot be inlined, which is the runtime cost of dynamic dispatch.

**Object slicing** happens when you copy a derived object into a base **value**:

```cpp
Sq s; Shape copy = s;   // only the Shape part is copied
```

The derived members and the derived vptr are lost. Use pointers or references to the base to keep the real type. (Our abstract `Shape` cannot be copied this way at all, which prevents the mistake.)
