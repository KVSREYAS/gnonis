## What SIMD is

A normal (scalar) add instruction adds one pair of numbers. A **SIMD** instruction adds several pairs at once, using wide **vector registers**.

On x86-64:

- **SSE**: 128-bit `xmm` registers. 4 floats, 2 doubles, or 4 int32s. Always available on x86-64.
- **AVX/AVX2**: 256-bit `ymm`, 8 floats.
- **AVX-512**: 512-bit `zmm`, 16 floats, on some CPUs.

Each slot in the register is a **lane**. `addps` adds lane 0 to lane 0, lane 1 to lane 1, and so on, in about the same time as one scalar add. A loop over floats can therefore run up to 4 times (SSE) or 8 times (AVX) faster when it is limited by arithmetic.

## Auto-vectorization

At `-O2` (GCC 12 and newer) and `-O3`, the compiler tries to turn loops into SIMD code. It succeeds when:

1. Iterations are **independent**: iteration i does not need the result of i-1.
2. Memory is accessed with a simple stride, ideally contiguous.
3. It can prove arrays do not overlap, or it adds a runtime check.
4. There are no function calls it cannot inline.

```cpp
void add(float* __restrict a, const float* __restrict b, int n) {
    for (int i = 0; i < n; ++i) a[i] += b[i];   // vectorizes
}
```

`__restrict` promises no overlap. Check the result with `-fopt-info-vec` (GCC) or by reading the assembly for `ps` (packed single) instructions like `addps`.

## Intrinsics

**Intrinsics** are functions that map one-to-one to specific instructions. They let you write SIMD by hand.

```cpp
#include <emmintrin.h>
void add4(float* a, const float* b) {
    __m128 va = _mm_loadu_ps(a);   // load 4 floats (unaligned ok)
    __m128 vb = _mm_loadu_ps(b);
    _mm_storeu_ps(a, _mm_add_ps(va, vb));
}
```

Naming: `_mm_` = 128-bit, `add` = operation, `ps` = packed single-precision. `__m128` is the register type. `_mm_load_ps` (no `u`) requires 16-byte alignment.

For an array whose length is not a multiple of 4, process groups of 4 and then finish the remaining 0-3 elements with a scalar **tail loop**.

## Reductions

A **reduction** combines many values into one, such as a sum. `s += x[i]` has a dependency: each add needs the previous `s`. A float add has a latency of about 4 cycles, so the loop is limited to one add per 4 cycles.

Fix: keep several independent **accumulators** and combine them at the end.

```cpp
float s0 = 0, s1 = 0, s2 = 0, s3 = 0;
for (int i = 0; i + 3 < n; i += 4) {
    s0 += x[i]; s1 += x[i+1]; s2 += x[i+2]; s3 += x[i+3];
}
float s = (s0 + s1) + (s2 + s3);   // plus a tail loop
```

Floating-point addition is not associative, so this changes the rounding a little. That is why the compiler will not do it for you without `-ffast-math` or `-fassociative-math`.

## FMA and horizontal operations

**FMA** (fused multiply-add) computes `a * b + c` in one instruction with one rounding step instead of two. `_mm256_fmadd_ps` does 8 of them at once. It needs the FMA3 extension (Haswell and newer, enabled by `-mfma` or `-march=native`). It is not in baseline SSE2, so this site's runner does not use it. Because there is one rounding instead of two, results can differ slightly from separate multiply and add.

A **horizontal** operation combines lanes **within** one register, for example adding the 4 floats of an `__m128` into a single float. These are slower than vertical (lane by lane) operations, so SIMD code keeps sums vertical inside the loop and does one horizontal sum at the end:

```cpp
__m128 shuf = _mm_movehl_ps(v, v);   // lanes 2,3 into 0,1
__m128 s = _mm_add_ps(v, shuf);      // 0+2, 1+3
s = _mm_add_ss(s, _mm_shuffle_ps(s, s, 1));
float total = _mm_cvtss_f32(s);
```
