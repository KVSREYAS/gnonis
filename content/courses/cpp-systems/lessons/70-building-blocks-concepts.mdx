## Milestone 13: the engine core

**What we build this module:** three pieces the rest of the game stands on. A **frame arena** for scratch memory that lives exactly one frame, an **SPSC ring buffer** that carries sound commands from the game thread to the audio thread, a **job system** (thread pool) that spreads the slime AI over all cores, and in the module test a **projectile pool** that reuses bullet objects.

**Why the game needs it:** the profiler from the last module points at costs that are not in our own algorithms: thousands of small `new`/`delete` calls per frame, threads created and destroyed for tiny jobs, and an audio thread that must never wait for a lock. Each building block removes one of those costs.

## The careless version: new and delete for scratch data

Every frame, 100 slimes each run a 200-step path search, and each step allocates a node. All of it is garbage when the frame ends.

```cpp
#include <chrono>
#include <cstddef>
#include <cstdio>
#include <new>
#include <vector>

struct Node { int tile; float cost; Node* parent; };       // one step of a slime's path search
template <class T> void do_not_optimize(T const& v) { asm volatile("" : : "r,m"(v) : "memory"); }

int main() {
    const int frames = 200, searches = 100, steps = 200;
    auto ms = [](auto d) { return std::chrono::duration<double, std::milli>(d).count(); };

    auto t0 = std::chrono::steady_clock::now();
    for (int f = 0; f < frames; ++f)
        for (int s = 0; s < searches; ++s) {
            Node* last = nullptr;
            for (int i = 0; i < steps; ++i) last = new Node{i, 1.0f * i, last};
            do_not_optimize(last);
            while (last) { Node* p = last->parent; delete last; last = p; }
        }
    auto t1 = std::chrono::steady_clock::now();

    std::vector<std::byte> arena(1 << 20);
    for (int f = 0; f < frames; ++f) {
        std::size_t used = 0;                               // reset: the whole frame's scratch is free again
        for (int s = 0; s < searches; ++s) {
            Node* last = nullptr;
            for (int i = 0; i < steps; ++i) {
                last = new (arena.data() + used) Node{i, 1.0f * i, last};
                used += sizeof(Node);
            }
            do_not_optimize(last);
        }
    }
    auto t2 = std::chrono::steady_clock::now();
    std::printf("new/delete per node: %5.1f ms\n", ms(t1 - t0));
    std::printf("frame arena:         %5.1f ms\n", ms(t2 - t1));
}
```
```text
new/delete per node:  46.3 ms
frame arena:           2.4 ms
```

(One run at `-O2`, 200 frames.) The same nodes, built the same way. The arena version never frees a node: it sets `used = 0` at the start of each frame.

## Arena allocator

`new`/`malloc` must handle any size and any free order, so each call does bookkeeping. When many objects share one lifetime (everything for one frame), an **arena** is simpler:

1. Reserve one large block.
2. Keep an **offset**, the first unused byte.
3. To allocate n bytes: round the offset up to the required alignment, return that address, add n.
4. Never free single objects. **Reset** the offset to 0 to free everything at once.

Destructors are not run, so store only trivially destructible types, or call them yourself.

## SPSC ring buffer

A **ring buffer** is a fixed array used in a circle. **SPSC** means single producer, single consumer: exactly one thread pushes (the game thread) and one pops (the audio thread).

Two counters only ever grow: one counts items written (written only by the producer), the other counts items read (written only by the consumer). Both are `std::atomic<size_t>`. Empty when they are equal; full when they differ by the capacity. The slot for counter `c` is `c % cap`, or `c & (cap - 1)` when the capacity is a power of two.

The producer writes the slot, then publishes its counter with **release**; the consumer loads it with **acquire**, so it sees the slot's data. No mutex is needed because each counter has one writer.

## Thread pool

Creating a thread costs tens of microseconds. A **thread pool** creates N workers once and reuses them:

1. A queue of tasks (`std::function<void()>`), protected by a mutex.
2. A `std::condition_variable` that sleeping workers wait on.
3. Worker loop: lock, wait until the queue is non-empty or `stop` is set, pop a task, unlock, run it.
4. `submit(task)`: lock, push, unlock, `notify_one()`.
5. Shutdown: set `stop`, `notify_all()`, join every worker.

To return a result, wrap the task in `std::packaged_task` and hand the caller a `std::future`. N is usually the number of hardware threads.
