## Milestone 14: the slime king's brain

**What we build this module:** the final boss's decision-maker. Each frame the game packs what the boss can see (distance to the player, the player's health, its own health, how many minions are alive) into a list of numbers. A small neural network turns that into one score per action: slam, jump, summon, retreat. Softmax turns the scores into probabilities, and the boss samples its move.

**Why the game needs it:** a hand-written `if` tree makes a boss players learn in three tries. A small trained network gives varied, situation-aware behaviour, and it is cheap: a few small matrix multiplies per decision. This capstone uses every earlier module: flat arrays, cache-friendly loops, SIMD-friendly inner loops, and careful floating point. These are also exactly the pieces of a language model's forward pass; there, the "actions" are the next word.

## The careless version: softmax straight from the formula

```cpp
#include <cmath>
#include <cstdio>

const char* actions[4] = {"slam", "jump", "summon", "retreat"};

void softmax_naive(const float* z, float* p, int n) {
    float s = 0;
    for (int i = 0; i < n; ++i) s += std::exp(z[i]);
    for (int i = 0; i < n; ++i) p[i] = std::exp(z[i]) / s;
}

int main() {
    float calm[4] = {2.0f, 1.0f, 0.5f, 0.1f};           // early in the fight
    float enraged[4] = {95.0f, 91.0f, 90.0f, 10.0f};    // low health: the network is very sure
    float p[4];
    const float* fights[2] = {calm, enraged};
    for (const float* z : fights) {
        softmax_naive(z, p, 4);
        for (int i = 0; i < 4; ++i) std::printf("%s %.3f  ", actions[i], p[i]);
        std::printf("\n");
    }
}
```
```text
slam 0.575  jump 0.211  summon 0.128  retreat 0.086  
slam -nan  jump -nan  summon -nan  retreat 0.000  
```

At low health the network's scores are large, `exp(95)` overflows a float to infinity, and infinity divided by infinity is NaN. The one finite score (retreat) gets probability 0. With NaN probabilities, the sampling code below picks a fallback action or none at all: the boss freezes at the dramatic moment.

## Tensors are flat arrays

A **tensor** is a multi-dimensional array of numbers. In memory it is always one flat buffer. Two extra lists describe it:

- **shape**: size of each dimension, e.g. `[2, 3]` (2 slimes, 3 features each)
- **strides**: how many elements to skip to move by one in each dimension

For a row-major `[2, 3]` tensor the strides are `[3, 1]`, and element `(i, j)` lives at offset `i*3 + j*1`. A **transpose** just swaps shape and strides, `[3, 2]` with strides `[1, 3]`, without moving data. The result is **non-contiguous**: walking its last dimension jumps through memory.

## Matrix multiplication

A network layer is a matrix multiply: inputs `[M, K]` (M slimes, K features) times weights `[K, N]` gives `[M, N]`:

```cpp
for (int i = 0; i < M; ++i)
  for (int k = 0; k < K; ++k) {
    float a = A[i*K + k];
    for (int j = 0; j < N; ++j) C[i*N + j] += a * B[k*N + j];
  }
```

That is `2*M*N*K` floating-point operations. The i-k-j order makes the inner loop walk B and C contiguously. **Tiling** splits the loops into blocks that fit in cache, so each loaded value is reused many times.

## Softmax

The network outputs **logits**: one raw score per action. **Softmax** converts them to probabilities that are positive and sum to 1: p_i = exp(z_i) / sum of exp(z_j).

Subtracting the same number from every z does not change the result, so compute it safely:

1. m = max(z)
2. e_i = exp(z_i - m), all now at most 1
3. s = sum of e_i
4. p_i = e_i / s

Example: z = [2, 1, 0]. m = 2. e = [1, 0.368, 0.135]. s = 1.503. p = [0.665, 0.245, 0.090].

## Sampling the next action

- **Greedy**: pick the largest p. Deterministic, so predictable.
- **Temperature T**: divide logits by T before softmax. T below 1 sharpens the distribution, above 1 flattens it. A difficulty knob.
- **Top-k**: keep only the k largest, renormalize, sample.
- **Random sampling**: draw u uniformly in [0, 1), walk the cumulative sum of p, return the first index where the sum exceeds u.

**Top-p** keeps the smallest set of actions whose probabilities add up to at least p. In a language model, the **KV cache** stores each earlier token's attention keys and values so they are not recomputed; the inference course covers it.
