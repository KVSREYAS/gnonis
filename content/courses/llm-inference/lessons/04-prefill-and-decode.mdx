## Two phases

Generating text is a loop, but the first iteration is special.

**Prefill.** The whole prompt goes through the model in one forward pass. All positions are
processed in parallel as big matrix-matrix multiplies. The logits at the last position give the
first output token.

**Decode.** Now the model produces one token per forward pass. Each step feeds in just the newest
token and gets back the next one. This continues until an end-of-sequence token or a length limit.

## The two latency numbers

Users feel two different delays:

- **TTFT** (time to first token): how long prefill takes, plus any queueing.
- **TPOT** (time per output token), also called inter-token latency: the gap between streamed
  tokens during decode.

Total time for an answer of $N$ tokens is roughly:

$$T \approx \text{TTFT} + (N - 1) \times \text{TPOT}$$

## Different bottlenecks

Prefill of 2,000 prompt tokens loads each weight once and uses it 2,000 times. That is plenty of
maths per byte, so the GPU's compute units are the limit.

Decode at batch size 1 loads **every weight** to process **one token**. The tensor cores (the GPU
units that do matrix multiplication, covered in module 4) sit mostly idle, waiting on memory. That one fact drives batching, quantization and speculative decoding,
which you will meet later.

## Why each phase has its own limit

Both phases do roughly the same maths per token. What differs is how often each weight is reused once it has been read from memory.

**Prefill**: all prompt tokens go through the model together, so each weight is loaded once and used for every prompt token. Lots of maths per byte read, so the tensor cores are the bottleneck. Prefill is **compute-bound**.

**Decode**: one new token per step, and the step must still read every weight. The tensor cores finish their small share almost at once and then wait for memory. Decode is **memory-bound**.

So a faster chip only helps the phase whose limit it raises: more compute speeds up prefill, more memory bandwidth speeds up decode. When you read a GPU spec sheet, ask which phase your users mostly wait on.
