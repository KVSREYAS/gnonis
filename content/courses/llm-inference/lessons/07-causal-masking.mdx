## No peeking

When a model learns to predict token $i+1$, it must not see token $i+1$. So in a decoder, token
$i$ may only attend to positions $0 \dots i$.

The **causal mask** enforces this. Before softmax, every score above the diagonal is set to
$-\infty$. Since $e^{-\infty} = 0$, those keys get exactly zero weight.

## Why order matters

The mask has to come **before** softmax. Softmax normalises over whatever is left, so each row
still sums to 1.

During training, masking lets the model learn from every position of a sequence in one pass. At
inference, decode computes just one new row (the newest query) against all cached keys. That row
has no future keys anyway.

## Spot the leak

Off-by-one errors in mask code are a classic bug. They do not crash. The model just quietly
learns to cheat, and then falls apart at generation time.
