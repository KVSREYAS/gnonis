## Mission briefing

Attention is the friend who orders for the whole table. Double the context and the score matrix grows fourfold.

**Mission:** The attention tab just arrived. Find out why doubling the guest list quadrupled the bill.

## n squared

For $n$ tokens, each head computes an $n \times n$ score matrix. Going from 4k to 128k context
is 32x more tokens but **1,024x** more scores.

The FLOPs grow the same way. $QK^\top$ and the weighted sum over $V$ each cost about
$2 n^2 d_{head}$ per head. The MLP grows only linearly with $n$, so at long context, attention
dominates prefill.

## Do not materialise it

A naive implementation writes the full score matrix to GPU memory, softmaxes it, and reads it
back. Try the meter: at long context that matrix alone dwarfs the model.

## Tile it instead

The fix is to never store it. **FlashAttention** streams tiles of $K$ and $V$ through fast
on-chip memory and keeps a running softmax. The FLOPs stay the same, but the memory traffic
collapses.

## One query, by hand

During decode there is only one new query per head, so the "matrix" is a single row. Write that
row's computation yourself.

  solution={"import math\n\ndef attend(q, keys, values):\n    d = len(q)\n    scores = [sum(a * b for a, b in zip(q, k)) / math.sqrt(d) for k in keys]\n    m = max(scores)\n    w = [math.exp(s - m) for s in scores]\n    z = sum(w)\n    w = [x / z for x in w]\n    return [sum(w[i] * values[i][j] for i in range(len(values))) for j in range(len(values[0]))]\n"}
  hints={["Scale with math.sqrt(len(q)).","Subtract the max score before exponentiating."]}
  explanation="This is exactly what one decode step does per head, for the newest query against every cached key."
