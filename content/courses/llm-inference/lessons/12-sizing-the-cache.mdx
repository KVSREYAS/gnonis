## The formula

For every token, every layer stores one key and one value vector per KV head:

$$\text{bytes/token} = 2 \times L \times H_{kv} \times d_{head} \times b$$

- $2$: one K and one V.
- $L$: number of layers.
- $H_{kv}$: KV heads (fewer than query heads with GQA).
- $d_{head}$: head dimension.
- $b$: bytes per element (2 for fp16 and bf16, 1 for fp8). fp16 and bf16 are two 16-bit floating-point formats, and fp8 is an 8-bit format (module 7).

## A real model

Llama 3 8B: $L = 32$, $H_{kv} = 8$, $d_{head} = 128$, with an fp16 cache:
$2 \times 32 \times 8 \times 128 \times 2 = 131{,}072$ bytes, or 128 KiB per token.

Notice what is missing from the formula: query heads. Queries are never cached, so only the
KV heads count.

## Comparing real models

The same formula gives very different answers for real models (fp16 cache, head size 128):

| Model | Layers | KV heads | Per token |
|---|---|---|---|
| Llama 2 7B | 32 | 32 (MHA) | 512 KiB |
| Llama 3 8B | 32 | 8 (GQA) | 128 KiB |
| Llama 3 70B | 80 | 8 (GQA) | 320 KiB |

Llama 3 70B has nearly 9x the parameters of Llama 3 8B, but only 2.5x the cache per token, because only layers and KV heads matter. Llama 2 7B, a smaller model, needs 4x more cache per token than Llama 3 8B, because it uses MHA.

Parameter count tells you the weight memory. The attention shape tells you the cache.

## Per sequence

At 128 KiB per token, an 8,192-token conversation needs
$131{,}072 \times 8{,}192 \approx 1.07$ GB, just for one sequence's cache.
