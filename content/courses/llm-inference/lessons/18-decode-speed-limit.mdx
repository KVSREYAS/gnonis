## Mission briefing

At batch 1, your 1,000-TFLOP GPU is a Ferrari stuck behind a garbage truck called HBM.

**Mission:** One user, one car, batch 1. Work out the speed limit, then cheat it legally.

## Back-of-envelope decode

At batch 1 every decode step reads all the weights once. If memory is the bottleneck (it is), the
step time is about:

$$t_{step} \approx \frac{\text{weight bytes} + \text{KV bytes}}{BW}$$

For an 8B fp16 model on an H100, $16\text{ GB} / 3.35\text{ TB/s} \approx 4.8$ ms per token,
which is about **209 tokens/s**. That is the ceiling. Kernel launch gaps, the KV reads and
sampling all eat into it.

## Pulling the levers

To decode faster for a single user, read fewer bytes or read them faster:

- **Quantize** weights to int8 or int4 (module 7).
- Use a GPU with more **bandwidth**.
- **Split** the model across GPUs so each reads less (module 10).
- **Speculate**: verify several draft tokens per weight read (module 9).

## Sanity-check your models

Every estimator should have one line asking which limit binds. Forgetting that gives physically
impossible numbers.
