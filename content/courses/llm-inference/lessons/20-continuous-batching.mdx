## Why batch at all?

At batch 1, decode reads every weight to produce **one** token (module 4). Put
32 sequences in the batch and the same weight read produces **32** tokens. Throughput climbs almost
linearly until you hit the compute roof or run out of KV memory.

## The longest-request problem

In a static batch, every slot stays reserved until the longest request finishes.

## Iteration-level scheduling

Orca (OSDI 2022) proposed scheduling per **iteration**. An iteration is one forward pass of the
whole batch, which gives every running sequence one new token. After every iteration, finished
sequences leave and waiting ones join. New requests join by running their prefill in that
iteration, mixed with the other sequences' decode tokens. vLLM, TGI (Hugging Face Text Generation Inference), SGLang and TensorRT-LLM (which calls it
"in-flight batching") all do this.

## What the papers measured

Orca (OSDI 2022) introduced iteration-level scheduling: the batch is re-decided at every step, so a finished request leaves at once and a waiting one can join. To mix requests at different positions, it batches the matmuls across all tokens but runs attention per request ("selective batching"), because each request has its own cache length.

vLLM (SOSP 2023) combined continuous batching with paged KV memory and reported 2–4x higher throughput than FasterTransformer and Orca at the same latency, with bigger gains for longer sequences and larger models. Most of that gain came from fitting more sequences in memory, so the batch could grow.

Sources: [Orca](https://www.usenix.org/conference/osdi22/presentation/yu), [vLLM](https://arxiv.org/abs/2309.06180)

## Summary

Static batching admits new requests only after every request in the batch has finished. Continuous batching
removes a finished request and admits a waiting one at every decode step, so slots never sit idle.

Sources: [Orca, OSDI 2022](https://www.usenix.org/conference/osdi22/presentation/yu), [Anyscale: continuous batching](https://www.anyscale.com/blog/continuous-batching-llm-inference)
