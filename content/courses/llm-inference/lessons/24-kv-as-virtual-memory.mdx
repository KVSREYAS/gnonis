## The fragmentation tax

Older servers reserved one contiguous KV slab per request, sized for the maximum length. Most of it was
never written. The vLLM authors measured only 20.4% to 38.2% of KV memory holding real token states.

<MCQ
  id="waste-slab"
  devices={["phone","desktop"]}
  prompt={"Why did older servers reserve one contiguous KV slab sized for the maximum length, even though most of it was never used?"}
  options={["GPUs can only allocate memory in maximum-length units.", "Attention needs the unused space as workspace for its score matrix.", "They could not know the output length in advance, and a contiguous buffer cannot grow in place once other requests sit next to it.", "Each request needs room for its own copy of the weights."]}
  answer={2}
  explanation={"The output length is unknown when a request starts, and a contiguous buffer cannot be extended once neighbours are allocated after it, so servers reserved the worst case. That is where the reservation waste and fragmentation came from. GPUs can allocate any size, the score matrix is not stored in the KV slab, and all requests share one copy of the weights."}
/>

## Pages, but for keys and values

PagedAttention splits the cache into fixed blocks (16 tokens by default in vLLM). A sequence grabs a
new block only when the last one fills up, so it wastes at most one partly-filled block.

Block size is a trade-off. Bigger blocks waste more slots in each sequence's last block. Smaller
blocks mean longer block tables and smaller, more scattered reads for the attention kernel.

<MCQ
  id="blocks-needed"
  devices={["phone","desktop"]}
  prompt={"You change the KV block size from 16 tokens to 256. What happens?"}
  options={["Block tables get shorter, but each sequence can now waste up to 255 slots in its last block, so fewer sequences fit.", "Waste goes down, because there are fewer blocks to track.", "Nothing changes for memory; block size only affects speed.", "Prefix sharing stops working."]}
  answer={0}
  explanation={"A sequence wastes at most one partly filled block, so the worst-case waste per sequence grows from 15 slots to 255. Across many short sequences that adds up and cuts concurrency. Fewer blocks to track does not mean less waste. Block size clearly affects memory. Full blocks can still be shared at any block size."}
/>

## The block table

Each sequence keeps a table from logical block numbers (its 1st, 2nd, 3rd block of tokens) to physical
blocks (where in GPU memory those tokens' K and V actually sit). Operating systems use the same
structure, a page table, to map virtual memory pages to physical memory.
Physical blocks can sit anywhere, and two sequences can point at the same block to share a prompt prefix.

## Background

Operating systems have used paged virtual memory since the 1960s. vLLM applied the same idea to the KV cache in 2023 (SOSP paper).

Sources: [Kwon et al., SOSP 2023](https://arxiv.org/abs/2309.06180), [vLLM blog](https://blog.vllm.ai/2023/06/20/vllm.html)
