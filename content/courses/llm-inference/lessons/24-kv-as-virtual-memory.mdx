## The fragmentation tax

Older servers reserved one contiguous KV slab per request, sized for the maximum length. Most of it was
never written. The vLLM authors measured only 20.4% to 38.2% of KV memory holding real token states.

## Pages, but for keys and values

PagedAttention splits the cache into fixed blocks (16 tokens by default in vLLM). A sequence grabs a
new block only when the last one fills up, so it wastes at most one partly-filled block.

Block size is a trade-off. Bigger blocks waste more slots in each sequence's last block. Smaller
blocks mean longer block tables and smaller, more scattered reads for the attention kernel.

## The block table

Each sequence keeps a table from logical block numbers (its 1st, 2nd, 3rd block of tokens) to physical
blocks (where in GPU memory those tokens' K and V actually sit). Operating systems use the same
structure, a page table, to map virtual memory pages to physical memory.
Physical blocks can sit anywhere, and two sequences can point at the same block to share a prompt prefix.

## How the kernel reads scattered blocks

The PagedAttention kernel receives each sequence's block table. To compute attention for a new query, it walks through the table: for logical block i it looks up the physical block, loads that block's keys and values, and computes the scores for those 16 tokens. Then it moves on to the next entry.

Token index t lives in logical block t // 16, at slot t % 16. Physical blocks can sit anywhere in GPU memory, so a sequence never needs a contiguous region.

The extra lookup costs a little time compared with one contiguous buffer, but it lets almost the whole pool be used and lets sequences share blocks.

## Background

Operating systems have used paged virtual memory since the 1960s. vLLM applied the same idea to the KV cache in 2023 (SOSP paper).

Sources: [Kwon et al., SOSP 2023](https://arxiv.org/abs/2309.06180), [vLLM blog](https://blog.vllm.ai/2023/06/20/vllm.html)
