## Know your pool

At startup vLLM profiles memory, subtracts weights and activations, and carves the rest into fixed blocks. A running sequence holds enough blocks for its tokens, takes one more each time its last block fills, and gives them all back when it finishes.

## Preempt: swap or recompute

**Preemption** means pausing a running sequence and taking its KV blocks away, so that other sequences can keep growing. vLLM schedules requests **first-come-first-served (FCFS)**: older requests have priority, so when decoding needs a block and none are free, it preempts the most recently arrived sequences first.

- **Swap** copies the preempted sequence's blocks to CPU RAM over PCIe. When blocks free up, they are copied back and decoding continues.
- **Recompute** frees the blocks and puts the request back in the waiting queue. When it is resumed, the server runs prefill again on the prompt **plus the tokens already generated**, which rebuilds the same KV cache, and decoding continues.

Recompute is often cheaper, because prefill is compute-efficient and PCIe is slow. The current vLLM engine (V1) uses recompute only.

Sources: [vLLM paper §4.5](https://arxiv.org/abs/2309.06180), [vLLM docs: preemption](https://docs.vllm.ai/en/latest/configuration/optimization.html)

## Preemption in practice

Preemption keeps the server running when memory is short, but every preempted request repeats work. If it happens often, latency suffers.

vLLM logs a warning each time a request is preempted for lack of KV space, and exposes a preemption count in its metrics. Its docs list the levers: give the cache more memory (leave `gpu_memory_utilization` unset or raise it), lower `max_num_seqs` or `max_num_batched_tokens` so fewer requests run at once, or raise tensor or pipeline parallelism so each GPU holds fewer weights and has more room for cache.

An fp8 KV cache helps for the same reason: each token takes half the bytes, so the same pool holds twice as many tokens.

Source: [vLLM docs: optimization](https://docs.vllm.ai/en/latest/configuration/optimization.html)
