## Know your pool

At startup vLLM profiles memory, subtracts weights and activations, and carves the rest into fixed blocks. Every running sequence needs ceil(tokens / 16) of them, plus room to grow.

## Preempt: swap or recompute

**Preemption** means pausing a running sequence and taking its KV blocks away, so that other sequences can keep growing. vLLM schedules requests **first-come-first-served (FCFS)**: older requests have priority, so when decoding needs a block and none are free, it preempts the most recently arrived sequences first.

- **Swap** copies the preempted sequence's blocks to CPU RAM over PCIe. When blocks free up, they are copied back and decoding continues.
- **Recompute** frees the blocks and puts the request back in the waiting queue. When it is resumed, the server runs prefill again on the prompt **plus the tokens already generated**, which rebuilds the same KV cache, and decoding continues.

Recompute is often cheaper, because prefill is compute-efficient and PCIe is slow. The current vLLM engine (V1) uses recompute only.

Sources: [vLLM paper §4.5](https://arxiv.org/abs/2309.06180), [vLLM docs: preemption](https://docs.vllm.ai/en/latest/configuration/optimization.html)
