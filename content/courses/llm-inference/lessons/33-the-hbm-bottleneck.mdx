## The N² matrices

Naive attention runs as separate kernels, and each one writes its N×N result to HBM for the next to read. With 4k tokens and 32 heads that's a GiB per matrix per layer.

## IO, not FLOPs

Dao et al. counted HBM reads and writes. For standard attention they grow like N·d + N² (the N² is the score matrix). For FlashAttention they grow like N²·d² / M, where M is the SRAM size per SM. With d = 128 and M around 100 KB, d²/M is well below 1, so FlashAttention moves many times fewer bytes. The FLOPs are the same.

Source: [FlashAttention](https://arxiv.org/abs/2205.14135)

## The numbers at 16k tokens

At N = 16,384 tokens, one head's score matrix has N² ≈ 268 million entries. In fp16 that is 512 MiB for S and another 512 MiB for P, per head, per layer.

Naive attention writes S, reads it back for the mask and softmax, writes P, and reads it again for the multiplication by V. Each of these passes moves hundreds of MB while doing only a few operations per element, so the work is memory-bound.

The output O is only N × d = 16,384 × 128 values, 4 MiB in fp16. Almost all of the traffic is intermediate data that is thrown away.
