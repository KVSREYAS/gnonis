## Guess, then check

A small draft model proposes several tokens. The big target model scores all of them in **one** forward
pass, which costs about the same as one decode step because decode is memory-bound.

## The accept rule

Verification checks the drafts in order. With greedy decoding, draft token i is accepted if it equals the target's top choice at that position. With sampling, it is accepted with probability min(1, p(x) / q(x)), where p is the target's probability for that token and q the draft's. At the first rejection, the target samples a replacement from the leftover distribution max(0, p − q), normalised, and the remaining drafts are thrown away.

If every draft is accepted, the target's prediction at the last position is still unused, so it gives one extra token for free: the **bonus token**. One target pass therefore yields between 1 and γ + 1 tokens.

## How many tokens per pass?

If each draft token is accepted with probability alpha (α) and the draft proposes gamma (γ) tokens, the
expected number of tokens per target pass is (1 - alpha^(gamma+1)) / (1 - alpha). This is the same
formula as the concept page, with a = α and k = γ. It assumes each draft is accepted independently.

## When it backfires

Speculation spends spare compute to save memory-bound steps.

<MCQ
  id="when-bad"
  devices={["phone","desktop"]}
  prompt="When does speculative decoding help least?"
  options={["Batch 1 on a big GPU","Very large batches where the GPU is already compute-bound","Code completion with repetitive text","When the draft model is very well aligned"]}
  answer={1}
  explanation={"Speculation spends spare compute. At high batch there is no spare compute left, so the extra verification work can slow you down."}
/>

## Variants

Variants worth knowing: Medusa (extra decoding heads), EAGLE (feature-level drafting) and prompt-lookup
or n-gram drafting.
