## Column, then row

Megatron-LM shards the first MLP weight by columns (each GPU computes part of the hidden layer) and the second by rows (partial outputs), then sums them with one all-reduce. Attention splits by heads the same way.

## TP in practice

In vLLM, TP is one flag: `--tensor-parallel-size 4` splits every layer across 4 GPUs. TensorRT-LLM sets the TP degree when it builds the engine.

Weights per GPU shrink by the TP degree, and so do the bytes each GPU reads per step, which is why TP speeds up a single user. The memory that is freed goes to the KV cache, which is also split by heads across the GPUs.

The usual choice is the smallest TP degree whose per-GPU weights leave enough room for the KV cache you need. Spare GPUs then run extra **replicas** (data parallelism), which add throughput with no communication between them.

## Communication cost

Each all-reduce moves about twice the activation size per GPU. The common **ring all-reduce** arranges N GPUs in a ring and cuts the tensor into N pieces. Phase 1 (reduce-scatter): in N − 1 rounds, each GPU sends one piece to its neighbour and adds the piece it receives, so each GPU ends up with the full sum of one piece. Phase 2 (all-gather): in another N − 1 rounds, the summed pieces are passed around until every GPU has all of them. Each round sends 1/N of the tensor, so each GPU sends 2(N − 1)/N times the tensor size in total.

That is fast on NVLink and painful across nodes.

Source: [Megatron-LM](https://arxiv.org/abs/1909.08053)
