## Two clocks

**TTFT** covers queueing plus prefill. **TPOT** (or inter-token latency) is the gap between later tokens.

![Latency timeline with TTFT and TPOT marked, and a radix tree of requests sharing a cached system prompt](/diagrams/llm-inference/11-serving-systems/01-ttft-tpot-and-prefix-caching.png)

## Where TTFT and TPOT come from

TTFT = time waiting in the queue + prefill time (+ network). TPOT = decode step time, which depends on the batch and on context lengths.

Each has its own levers:

- **TTFT**: shorter queues (more capacity, better admission), less prefill work (prefix caching, shorter prompts), faster prefill (more tensor parallelism, FP8).
- **TPOT**: fewer bytes per step (quantized weights, an FP8 KV cache), fewer steps (speculative decoding), smaller batches, and no prefill stalls (chunked prefill or disaggregation).

Measure the queue wait separately. A TTFT spike at peak hours with normal prefill times is a capacity problem, not a kernel problem.

## End-to-end latency

Total time is roughly TTFT plus TPOT for every token after the first.

## Prefix caching

If many requests start with the same system prompt, keep its KV blocks and skip that part of prefill.

How vLLM finds a match: each **full** KV block gets a hash computed from its own tokens **and** the hash of the block before it. So two blocks have the same hash only if the whole prompt up to and including that block is the same. A new request hashes its prompt block by block, reuses every block already in the cache, and prefills only the rest. Keys and values depend on all earlier tokens, which is why the hash must cover the whole prefix and not just one block.

vLLM calls this automatic prefix caching. SGLang keeps cached prefixes in a radix tree (RadixAttention), where requests with a shared beginning share a path from the root.

## Summary

Tokens per second alone hides latency. A server can have high total throughput while single users wait
a long time for the first token. Report TTFT and TPOT percentiles together with throughput.
