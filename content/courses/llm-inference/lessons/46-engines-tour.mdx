## Datacenter engines

**vLLM** is the default open-source server. **SGLang** adds RadixAttention and a structured-generation frontend (it can force output to match a format such as a JSON schema), and shines on prefix-heavy and agent workloads. **TensorRT-LLM** compiles models into optimised NVIDIA engines with in-flight batching and FP8/FP4.

## Local engine

**llama.cpp** is pure C/C++ with GGUF files and runs everywhere from a Raspberry Pi to a Mac Studio. Ollama and LM Studio wrap it.

Sources: [vLLM](https://github.com/vllm-project/vllm), [SGLang](https://github.com/sgl-project/sglang), [TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM), [llama.cpp](https://github.com/ggml-org/llama.cpp)

<MCQ
  id="q4-bits"
  devices={["phone","desktop"]}
  prompt={"GGUF Q4_0 stores a separate fp16 scale for every 32 weights instead of one per tensor. Why spend the extra bits?"}
  options={["The scales hold the most significant bits of each weight.", "GPUs require one scale per 32 values.", "A large weight then stretches the step size of only its own 32 weights, so rounding error stays small everywhere else.", "It makes the file smaller."]}
  answer={2}
  explanation={"This is the same idea as per-group scales in GPTQ and AWQ. It costs 16 / 32 = 0.5 bits per weight, so Q4_0 is 4.5 bits per weight, slightly bigger than plain 4-bit, but far more accurate. The scale is one multiplier for the whole group, not extra bits of each weight, and no hardware demands groups of 32: it is a format choice that trades bits for accuracy."}
/>
