## Datacenter engines

**vLLM** is the default open-source server. **SGLang** adds RadixAttention and a structured-generation frontend (it can force output to match a format such as a JSON schema), and shines on prefix-heavy and agent workloads. **TensorRT-LLM** compiles models into optimised NVIDIA engines with in-flight batching and FP8/FP4.

![Four engines placed on a map: datacenter vs local, flexibility vs peak NVIDIA performance](/diagrams/llm-inference/11-serving-systems/02-engines-tour.png)

## Choosing an engine

- **vLLM**: a general-purpose open server with paged attention, continuous batching, prefix caching, many quantization formats and support for many kinds of hardware.
- **SGLang**: RadixAttention keeps cached prefixes in a radix tree, so requests that branch from shared prompts (agents, few-shot examples, multi-turn chat) reuse the shared part. It also offers fast structured output.
- **TensorRT-LLM**: NVIDIA's library that builds an optimized engine for a specific model and GPU, with in-flight batching and FP8 or FP4 support.
- **llama.cpp**: runs GGUF files on CPUs and on Apple, NVIDIA and other GPUs. Quantized types such as Q4_K_M or Q4_0 make 7–8B models practical on laptops.

The workload decides: prefix-heavy, local, or peak NVIDIA throughput.

## Local engine

**llama.cpp** is pure C/C++ with GGUF files and runs everywhere from a Raspberry Pi to a Mac Studio. Ollama and LM Studio wrap it.

Sources: [vLLM](https://github.com/vllm-project/vllm), [SGLang](https://github.com/sgl-project/sglang), [TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM), [llama.cpp](https://github.com/ggml-org/llama.cpp)

The scale is one multiplier for the whole group, not extra bits of each weight, and no hardware demands groups of 32: it is a format choice that trades bits for accuracy."}
