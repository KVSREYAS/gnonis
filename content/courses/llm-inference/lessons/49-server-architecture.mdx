## The components

Serving engines like vLLM split cleanly into an async API front, a scheduler with waiting, running and swapped queues, a KV block manager, a model runner that executes batched forwards, and a sampler plus detokenizer that stream tokens back.

## How big?

Little's law tells you how many sequences you'll hold at once, and so how many KV blocks you need.

Source: [vLLM architecture overview](https://docs.vllm.ai/en/latest/design/arch_overview.html)

## A capacity plan with Little's law

Little's law links three things: requests in the system = arrival rate × time each request spends there.

- If answers get longer, each request stays longer, so more requests are in flight at once.
- If the server slows down under load, the same thing happens, which is why load feeds on itself.
- Each request in flight holds a KV cache, so memory needed = requests in flight × cache per request.

The same law works in reverse for planning: measure the arrival rate and the time in system at peak, and you know how many requests, and how much KV cache, must fit at once.
