## The components

Serving engines like vLLM split cleanly into an async API front, a scheduler with waiting, running and swapped queues, a KV block manager, a model runner that executes batched forwards, and a sampler plus detokenizer that stream tokens back.

## How big?

Little's law tells you how many sequences you'll hold at once, and so how many KV blocks you need.

Source: [vLLM architecture overview](https://docs.vllm.ai/en/latest/design/arch_overview.html)

## A worked capacity plan

Little's law links three numbers: requests in the system = arrival rate × time each request spends there.

At 5 requests/s and 10 s per request, about 50 requests are in flight at once. If each holds about 2,000 tokens of context in Llama 3 8B (128 KiB per token), that is 50 × 2,000 × 128 KiB ≈ 13 GB of KV cache.

The same law works in reverse for planning: measure arrivals and time in system, and you know how many requests (and how much KV cache) must fit at peak.
