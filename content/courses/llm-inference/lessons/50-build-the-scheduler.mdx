## Decodes first

Running users are mid-conversation, so they always get their token. Their cost comes out of the step budget first, and new prompts get whatever is left.

Strict **FIFO** (first in, first out) admission takes waiting requests only from the front of the queue. If the request at the front does not fit, nothing behind it is admitted either, even small prompts that would fit. This is **head-of-line blocking**. Two fixes: chunk the big prompt so a piece of it always fits (module 5), or let the scheduler **skip ahead** and admit smaller requests behind it, with a limit so the big one is not starved forever.

## Fair admission

Strict FIFO is simple and fair in arrival order, but one big request at the head can block everything behind it. Two common fixes:

- **Chunking**: a long prompt enters in budget-sized pieces, so it never needs more than one step's leftover budget.
- **Bounded skip-ahead**: if the head doesn't fit, admit smaller requests behind it, but age the head so it can't be skipped forever.

Each fix trades something. Chunking adds extra KV reads for each chunk. Skip-ahead gives up strict arrival order. Real schedulers usually combine chunked prefill with a priority or FCFS order.
