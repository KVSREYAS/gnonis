      def matmul_intensity(m, k, n, bytes_per_elem=2):
          flops = 2 * m * k * n
          bytes_moved = bytes_per_elem * (m * k + k * n + m * n)
          return flops / bytes_moved

## FLOPs per byte

Every kernel does some maths and moves some data. Their ratio is the **arithmetic intensity**:

$$I = \frac{\text{FLOPs}}{\text{bytes moved}}$$

High intensity means each byte fetched from HBM feeds lots of maths. Low intensity means the
compute units spend most of their time waiting.

A matmul $[m \times k] \cdot [k \times n]$ does $2mkn$ FLOPs (a multiply and an add per term).

## Decode is a matrix-vector product

At decode time with batch size 1, each linear layer multiplies **one** token's vector by a big
weight matrix. Every weight is read once and used once.

<Exercise id="gemv-ai" />

## Batching to the rescue

Decode $B$ sequences together and each weight, loaded once, serves $B$ tokens. The intensity of
the weight matmuls rises to roughly $B$ FLOP/byte in fp16. This is the core reason servers batch.
